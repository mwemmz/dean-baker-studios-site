Why Semantic HTML Still Matters in 2025

By the Overhead blog  ·  5 min read

When CSS frameworks and component libraries do the heavy lifting, it is tempting to reach for a <div> for everything. Semantic HTML — using tags that describe their own meaning — can feel like ceremony. It is not.

[ Document outline — semantic structure ]

Accessibility is non-negotiable. Screen readers build a navigable page outline from semantic elements. A proper <nav>, a <main>, and a clean heading hierarchy let users jump to the content they need without any extra ARIA on your part. You get that for free — but only if you use the right tags.

The clearest sign of a junior developer's markup is a wall of nested divs with class names that are basically a second stylesheet.

SEO still cares. Search engines parse document structure to understand what a page is about. An <article> signals self-contained content. A <time datetime="..."> lets crawlers surface publication dates in rich results. These are honest signals, not tricks.

Maintainability improves. A developer reading <header>, <aside>, and <footer> immediately understands the page's regions without decoding class names. Semantic HTML is self-documenting code — a property that becomes more valuable as teams and codebases grow.

Quick checklist

One <h1> per page. Use <nav> for navigation, <main> for primary content, <article> for self-contained pieces, <section> for thematic groups, and <aside> for tangential material.

CSS Grid vs. Flexbox: Choosing the Right Tool

By the Overhead blog  ·  4 min read

After years of float hacks and clearfix nightmares, modern CSS gives us two genuinely powerful layout systems. The confusion arises because developers treat them as interchangeable. They are not — each has a domain where it shines.

[ Grid: 2D  |  Flexbox: 1D ]

Flexbox thinks in one dimension. It distributes items along a single axis — a navigation bar, a row of buttons, the internal layout of a card. When you want items to wrap naturally and the container to respond to its children's sizes, Flexbox is the right call.

Grid thinks in two dimensions. It places items across rows and columns simultaneously. Page-level layouts — header, sidebar, content, footer — belong to Grid. So do image galleries and dashboards where items must align across both axes at once.

Use Flexbox to control how items flow. Use Grid to control where items land.

In practice, the two work beautifully together: Grid handles the macro layout, while Flexbox handles the micro-layout inside each Grid cell. Picking the right tool for each layer removes the hacks and makes your CSS read like it means what it says.

Rule of thumb

If you're drawing rows and columns on a whiteboard, reach for Grid. If you're distributing items along a single line, reach for Flexbox.

5 Quick Wins for Faster Web Pages

By the Overhead blog  ·  3 min read

Performance is user experience. A one-second delay in load time can cut conversions by 7%. None of these changes require a rewrite.

[ PageSpeed Insights score: before / after ]

1. Switch to modern image formats. Replace JPEGs and PNGs with WebP or AVIF. You'll typically cut image payload by 30–50% with no visible quality loss. Add loading="lazy" to anything below the fold.

2. Minify CSS and JS. Strip whitespace, comments, and dead code before shipping. Tools like Vite and esbuild do this automatically in production builds — there is no reason to ship unminified assets.

3. Preconnect to critical origins. A <link rel="preconnect"> for third-party origins like Google Fonts cuts the DNS and TLS handshake time on the browser's critical path.

4. Defer non-critical JavaScript. Any script that doesn't need to run on first paint should carry the defer or async attribute. This keeps the browser from blocking HTML parsing to execute scripts.

5. Set long cache lifetimes on static assets. Fonts, images, and versioned CSS/JS files should carry max-age=31536000, immutable. Returning visitors will load your page almost instantly.

Measure first

Run your page through PageSpeed Insights before and after each change. Data beats intuition every time.
